# Змейка в APK: облачные модели как автономные агенты

Может ли модель **сама, без человека** собрать рабочее Android-приложение с нуля?
Одна задача, один промпт, пять облачных моделей. Каждая сама пишет проект,
сама запускает Gradle, сама читает ошибки и чинит их, пока не получится APK.

Материалы: [`snake-apk/`](../snake-apk) — скрипты агента, исходники всех змеек,
полные логи переписки с моделями и готовые APK.

---

## Коротко

| | Модель | Время | Ходов | Сборок до успеха | Код, строк Kotlin | Токены вход / выход |
|---|---|---|---|---|---|---|
| 🥇 | **gpt-6-astra** | **~5 мин** | 8 | 2 | 230 | **73k / 6.5k** |
| | gpt-6.1-sol | ~12 мин | 14 | 5 | 168 | 140k / 8k |
| | claude-opus-5-5 | ~13 мин | 13 | 2 | 820 | 621k / 60k |
| | kimi-k3 | ~15 мин | 7 | 2 | 410 | 107k / 22k |
| | glm-5.3 | ~16 мин | 14 | 2 | 732 | 572k / 55k |

**Все пять справились.** Ни одна модель не сдалась и не зациклилась — у всех
готовый APK, который ставится на телефон.

Отличаются они не тем, *смогут ли*, а **ценой**: Astra сделала то же самое
в 8 раз дешевле по токенам, чем Opus или GLM.

---

## Задача

Промпт одинаковый для всех (отличается только путь к папке проекта):

> Build a complete, playable Snake game as an Android APK. Work fully autonomously —
> nobody will answer questions. Iterate until `assembleDebug` succeeds.
> Kotlin, single-module app, package com.example.snake, swipe controls, score,
> game over + restart, speed increases over time, looks decent. Keep dependencies minimal.

Модели сказано, что есть: Gradle 8.11.1 (без wrapper), JDK 21, Android SDK
с платформами 34/35. **Шелла у модели нет** — только четыре инструмента:

| Инструмент | Что делает |
|---|---|
| `write_file` | записать файл в папку проекта |
| `read_file` | прочитать файл |
| `list_files` | список файлов проекта |
| `gradle` | запустить Gradle с аргументами, вернуть код выхода и хвост вывода |

Пути вне папки проекта отклоняются. Модель не может ничего сделать на машине,
кроме как писать файлы и собирать.

Агентный цикл — [`agent_openai.py`](../snake-apk/harness/agent_openai.py)
(OpenAI chat completions + function calling) и
[`agent_anthropic.py`](../snake-apk/harness/agent_anthropic.py) (Anthropic Messages,
только для первого прогона Opus). Лимит: 40 ходов или 1 час.

## Как вёл себя каждый

**gpt-6-astra.** Самый собранный. Каркас → игра → сборка. Одна ошибка,
исправлена с первого раза. Выходных токенов меньше всех — пишет ровно то, что нужно.

**gpt-6.1-sol.** Самый компактный код (168 строк), но **четыре раза споткнулся
о конфигурацию**, ни разу — о сам код игры:

1. взял AGP 8.11.1, который требует Gradle 8.13 → понизил до 8.9.1;
2. потребовал Java 17 toolchain при установленном JDK 21 → убрал;
3. рассинхрон target JVM у Java (1.8) и Kotlin → выровнял;
4. ещё одна правка сборки → собралось.

Каждую ошибку диагностировал правильно и с первого раза — просто их было много.

**claude-opus-5-5.** Больше всего кода (820 строк) — значит, вероятно, больше деталей
в самой игре. Две ошибки компиляции Kotlin (`pollFirst` у `ArrayDeque`, неполный `when`),
обе исправлены за ход. Цена — 621k входных токенов: каждая итерация тащит
за собой весь растущий контекст с крупными файлами.

**kimi-k3.** Медленнее всех на каждый ответ (в пробном вызове — 2 минуты на «создай
файл»), но **меньше всех ходов**: 7. Думает долго, делает точно.

**glm-5.3.** Много думает. Сработала только с третьей попытки, и обе неудачи —
проблемы *обвязки*, а не модели:

- без стриминга ответы GLM дольше 100 с, и Cloudflare перед прокси отдаёт **524**;
- в лимит 16k выходных токенов модель **целиком потратила на рассуждения**
  (15 998 из 16 000 — reasoning) и не успела вызвать ни одного инструмента.
  Скрипт принял обрезанный ответ за финиш.

Исправлено: стриминг, лимит 32k, обрезанный по лимиту ответ теперь не считается
завершением — модели говорится «ты упёрся в лимит, действуй». Время и токены
в таблице — только у последнего, успешного прогона.

## Вне зачёта: та же змейка руками Claude Code

Для сравнения ту же задачу сделал Claude Code (Opus 5.5) в обычной интерактивной
сессии — [`projects/claude-code-manual`](../snake-apk/projects/claude-code-manual):
584 строки, плавная интерполяция движения, рекорд, пауза, частицы.

Собралось с первой попытки. Но главное отличие не в коде, а в **проверке**:
приложение было установлено на эмулятор Pixel 8a и прогнано свайпами через `adb`
со скриншотами. Это нашло реальный баг, который сборка не показывает: **быстрый
флик приходил как DOWN+UP без MOVE и засчитывался как тап**. Исправлено.

Отсюда вывод: метрика «собралось» в этом бенчмарке слабая. Агенты выше
проверяли только компиляцию — у них такой баг остался бы незамеченным.

## Оговорки

- **Один прогон на модель.** Разброс между запусками не измерен.
- **Качество игры не оценивалось.** Метрика — дошла ли модель сама до рабочего APK.
  APK лежат в [`snake-apk/apk`](../snake-apk/apk) — играйте и сравнивайте.
- **Время — по стене часов.** Astra, Sol, Kimi и GLM шли параллельно, а сборки
  Gradle были сериализованы файловой блокировкой (16 ГБ RAM не тянут четыре
  Gradle разом), так что часть времени — ожидание очереди.
- **Opus шёл отдельно и раньше**, через Anthropic-формат API. Промпт тот же.
- **Доступ к моделям — через сторонний прокси-агрегатор** (OpenAI-совместимый API).
  Что именно стоит за названием модели, снаружи не проверить.
- Все приложения — с одинаковым `com.example.snake` (кроме ручной версии
  `com.example.snake.claude`), на телефоне каждое следующее заменяет предыдущее.

## Побочный результат: Claude Code через прокси в песочнице

Чтобы запускать модель с прокси как полноценный Claude Code, но без риска
для машины — [`claude-code-sandbox/`](../snake-apk/claude-code-sandbox):

- отдельный профиль через `CLAUDE_CONFIG_DIR` — основной Claude Code не затронут;
- `PreToolUse`-хук [`guard.py`](../snake-apk/claude-code-sandbox/guard.py) режет запись
  и чтение вне рабочей папки, рекурсивное удаление, реестр, shutdown, `curl | bash`,
  глобальные `pip`/`npm -g`, пути через `~`/`..`/переменные окружения, а также
  проверяет содержимое запускаемых скриптов;
- `disableBypassPermissionsMode` — флаг `--dangerously-skip-permissions` отключён.

Проверено 37 тестовыми случаями и живой попыткой модели «сбежать» из папки
(4 из 4 опасных действий заблокированы). Это защита на уровне правил,
а не песочница ОС: изощрённый код в теории может её обойти.
